# Proposal: 技能/攻击距离显示与棋将包系统

## Why

当前选择攻击或技能时，仅高亮「攻击范围内且已有敌将」的格子，玩家无法直观看到完整攻击范围，也难以判断「可移动但暂无目标」的格子。需要改为先展示全部可攻击格子，再按格内是否有目标决定是否可执行。此外，战斗前缺少布阵环节：玩家无法从己方棋将池中选择谁上场、放在哪一列，需要增加棋将包与拖拽布阵流程，并从配置表加载可选棋将。

## What Changes

- **攻击/技能范围显示**：选择攻击或技能后，高亮显示**所有**在攻击距离内的格子（不限于格内已有敌将）。仅当玩家点击的格子内存在可攻击目标时，攻击/技能才真正生效；点击范围内空格子视为无效或取消选择。
- **棋将包系统**：在战斗场面下方显示棋将包 UI；包内棋将从 `config/General.xlsx` 加载并展示（沿用现有 HeroConfig/GeneralConfigLoader）。玩家可将包内棋将拖拽到地图第 1 列或第 2 列进行布阵；布阵完成后点击「确认出战」再开始战斗。每场战斗中每个棋将只能被拖拽上场一次；已上场的棋将从包内移除或标记为已使用。

## Capabilities

### New Capabilities

- `attack-range-display`: 选择攻击/技能后高亮所有在攻击距离内的格子；仅当格内有可攻击目标时允许执行攻击/技能，否则不执行或取消选择。
- `deck-system`: 战斗下方棋将包 UI、从 General.xlsx 加载可选棋将、拖拽至地图第 1/2 列布阵、确认出战后开始战斗、每战每棋将仅可上场一次。

### Modified Capabilities

- （无现有规格需修改；实现上将扩展现有 FightBoard/ChessHero 的高亮与点击逻辑，以及新增布阵阶段与棋将包 UI。）

## Impact

- **配置**：沿用 `config/General.xlsx`，棋将包可选列表由该表全部或指定 ID 的棋将构成；若需「本关可用棋将」子集，可由关卡配置或现有表扩展决定。
- **代码**：FightBoard 或 ChessHero 需区分「攻击范围内的所有格子」与「范围内且格内有目标的格子」两套数据，高亮用前者、执行判定用后者；新增棋将包场景/脚本、布阵区域（第 1/2 列）与拖拽逻辑、「确认出战」按钮及与战斗开始的衔接；每战已上场棋将状态需在当局内维护。
- **依赖**：无新增外部依赖；沿用现有 Excel 配置与 Godot 节点体系。
